02

Data flow

Storage and clocks stay at the browser boundary. Pure functions receive explicit inputs; replay never reads the current browser history or wall clock.

Solid = synchronous calls/data flow. Dashed would mean asynchronous delivery; none is introduced. Terracotta border = new module. Engine, dealer and phase machine already exist.

Selection state

Keep one match seed and explicit per-slot PRNG state across rounds. A slot’s deal must not consume the other slot’s stream. Remove the currently discarded opponent deal on local line completion. Advance state only when a deal is committed, never as a React render side effect. Reconcile the existing unused RoundState.rngCursor with this ownership; do not maintain two independent cursors.

Startup and persistence

Server output and the client’s initial render both show the existing arena reveal with no dealt match yet. After mount, read validated history and create one seed using browser randomness. Initialize once, then start the reveal timer and match. Strict Mode effect re-runs must not create a second session, consume more randomness or append history twice. This explicitly handles localStorage being unavailable to the server; a seed alone cannot solve that mismatch.

Store a versioned ring of three entries containing session ID and distinct displayed line IDs for slot 0. Snapshot it once for selection. Commit at results once per session ID; invalid JSON or inaccessible storage falls back to in-memory history without blocking play. No keystrokes or stats are written to localStorage.

Replay contract

Version the record and include seed, arena, starting round/dev overrides, initial tuning, initial selection history, and a dictionary of every dealt line’s text/tier/word count. Store all offered option IDs and explicit PRNG checkpoints, including unchosen options, so later content edits cannot silently change a replay.

Events carry a monotonic sequence number, round identity and milliseconds relative to that round. Record deals, keys including backspace and incomplete lines, Special activation, tuning updates, and clock evaluations. Capture the effective input order; equal timestamps use sequence order. Damage, HP, momentum and winners are derived, never accepted as recorded outcomes.

The round driver applies the same keystroke → tick → resolve-once → tick ordering as the live hook, including trigger quick-draw. Keep a resolution guard in driver state and clear it on a new deal. Live input and replay both use this driver. The existing phase reducer remains the match sequencer and headless full-match verification drives it too. No timer loop or networking is added.

06

Validation

Prove replay equivalence and user-visible behavior, not just serialization.

  • Known PRNG vectors, immutability, same configuration/same deals, and independent slot streams across round boundaries.
  • Sufficient injected pools: no current-match or three-match repeats, initial offers counted, tiers preserved and distinct first characters when feasible. Tiny pools: deterministic fallback and no empty slot.
  • History: retain exactly three completed sessions; duplicate finalization is a no-op; malformed, stale-version and unavailable storage recover.
  • Replay: full match, both player slots in fixtures, errors/backspace, mid-line Special, tuning changes, incomplete timeout line, exact-deadline input, trigger completion, KO, and equal-time ordering. Verify known HP/carry outcomes as well as final-state equality.
  • Manual browser pass: no hydration warnings or opening re-deal, one session under Strict Mode, round/tier shortcuts, reload after completion, blocked storage, stable typing and impact beat. No browser E2E suite.
  • Before submission: pnpm test, pnpm typecheck, pnpm lint, pnpm build. These are planned checks; implementation has not started.

Assumption for review · exhaustion permits repeats

SPEC §3.6 currently promises never to repeat, but the committed pool has one trigger and six debate lines, with no roast/fight pool. Preserve playable matches: prefer lines unseen in both windows, then relax past-match exclusions, then current-match exclusions only if necessary. Keep the existing round/tier candidate fallback. Update the spec to name this exception if approved. Strict no-repeat with empty choices would require a different product decision.
