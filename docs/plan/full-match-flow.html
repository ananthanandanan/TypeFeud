Key code

The three places this is easy to get wrong: the end condition, the carry arithmetic, and the timer that must not become a loop.

packages/game/src/engine.ts — the end condition
/**
 * Has the round ended? SPEC §4.6 — deadline-based, called on keystrokes and
 * once at the boundary. This is not a loop and must never become one.
 *
 * Two ways to end. The deadline is the ordinary one. A player at 0 HP is the
 * other, and it applies in EVERY round, not only round 3: HP never rises, so
 * once someone reaches 0 the round's winner is arithmetically fixed and the
 * remaining seconds cannot change it. Round 3 differs only in what happens
 * next — it ends the match rather than the round (SPEC §2.7).
 *
 * Returns the argument unchanged while the round is live, so the caller can
 * skip a render.
 */
export function tickRound(state: RoundState, now: number): RoundState {
  if (state.status === "over") return state;

  const expired = now >= state.endsAt;
  const knockout = state.players.some((p) => p.hp <= 0);
  if (!expired && !knockout) return state;

  return { ...state, status: "over" };
}

/** Null while the round is live. Equal HP is a draw — neither player carries. */
export function roundResult(state: RoundState): RoundResult | null {
  if (state.status !== "over") return null;

  const [you, them] = state.players;
  const winner: PlayerSlot | null = you.hp === them.hp ? null : you.hp > them.hp ? 0 : 1;
  return { round: state.round, hp: [you.hp, them.hp], winner };
}
packages/game/src/engine.ts — the carry
/**
 * What a player starts a round with. SPEC §2.7.
 *
 * Only round 3 carries anything: rounds 1 and 2 each open at the base pool,
 * which is the whole point of them not being a best-of-three. The trigger is
 * worth deliberately less than a round (§2.2) — it sets the topic, it does not
 * swing the match.
 */
export function startingHp(
  rounds: readonly RoundResult[],
  slot: PlayerSlot,
  tuning: Tuning = DEFAULT_TUNING,
): number {
  const won = (name: RoundName) =>
    rounds.find((r) => r.round === name)?.winner === slot;

  const trigger = won("trigger") ? tuning.triggerWinHpBonus : 0;
  const carried = (["debate", "roast"] as const)
    .filter(won)
    .length * tuning.roundWinHpBonus;

  return tuning.roundBaseHp + trigger + carried;
}

/** Round 3 is the decider; the earlier rounds already paid out as HP. */
export function resolveMatch(rounds: RoundResult[]): MatchOutcome {
  const fight = rounds.find((r) => r.round === "fight");
  return { winner: fight?.winner ?? null, rounds };
}
apps/web/src/match/use-match.ts — one timer, and a countdown that isn't one
// The ONLY timer in the game (SPEC §4.6). It is a backstop: a round with a
// player still typing ends on their keystroke, because every keystroke runs
// tickRound. This fires for the round nobody finishes.
useEffect(() => {
  if (round.status === "over") return;
  const remaining = round.endsAt - (performance.now() - startedAt.current);
  const id = window.setTimeout(() => {
    setRound((current) => tickRound(current, current.endsAt));
  }, Math.max(0, remaining));
  return () => window.clearTimeout(id);
}, [round.round, round.status]);

06

Future scope & assumptions

Four decisions this plan makes on your behalf, and three things it deliberately leaves alone.

A 0-HP player ends rounds 1 and 2 too — is that right?

This is the decision the issue asks for, and the plan takes the position that a knockout ends any round. HP is monotonically non-increasing and the round carry is binary (+10 or nothing, not HP-proportional), so once a player reaches 0 nothing that happens in the remaining seconds can change the round result — running the clock out is dead time with a decided outcome on screen. §2.7 stays true as written, because a player at 0 necessarily has less HP at the end. What changes is only that "the end" can arrive early.

The alternative — clamp at 0 and play the round out — keeps the round durations fixed and gives the losing player something to do, which matters more once #7's ghost is applying real pressure. It is one condition in tickRound either way, so it stays cheap to reverse.

Decide with · you, at plan review · reversible in slice 1

Does momentum carry across rounds?

The spec does not say. The plan assumes no — a fresh HP pool gets a fresh meter, and a Special banked in the debate does not fire in the fight. Carrying it would make round 3 open with an instant haymaker for whoever ended round 2 hot, which cuts against §2.7's intent that the fight is where the match is decided. Written into §2.7 alongside the 0-HP rule.

Assumption · revisit at #12's tuning pass

Rounds 2 and 3 will serve debate lines

The pool holds one trigger line and six debate lines; roast and fight are unwritten. dealThree's candidates() already widens when a round runs dry, so a full match walks end to end today — it just reads as the same six lines three times. That is #11's job and this issue does not touch pool/: authoring roast and fight lines here would put content review inside a flow PR, and the demo does not need it.

Deferred to · #11 · content pipeline

The trigger has no provocation text

§2.2 wants a provocation ("dev_p has left you on read for 4 hours") and then the word. The pool has the word and not the setup, and the schema has no field for arena-level framing. The layout reserves the slot and leaves it empty rather than inventing a line, which invariant 3 forbids. #11 adds either an arena metadata file or a provocation round.

Deferred to · #11

Intermission is a beat, not a screen

The phase exists in the machine and holds for its 10 seconds showing the round result, because the machine is much harder to retrofit than the screen is. The taunt exchange itself is #8 and this issue renders nothing for it.

Deferred to · #8 · intermission and taunt exchange

Solo means the opponent never attacks

Until #7 there is no ghost, so the opponent's HP only moves when you land a line and you will win every round you do not self-damage your way out of. This is enough to exercise every branch except "you lose", which the tests cover directly. Worth saying out loud so the hand-check is not mistaken for a balance verdict — §9's open question stays open.

Verdict after · #7 and #11

The phase machine lives in apps/web, not packages/game

Round rules — the carry, the winner, the end condition — go in the engine where both ends will share them. The phase sequence and its timers go in apps/web/src/match/, because at Milestone 3 the server owns the sequence (#13, room lifecycle) and the client becomes a renderer of it. Keeping the reducer pure and React-free means #13 moves the file rather than rewriting it.
